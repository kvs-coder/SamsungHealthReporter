# 8. Crosscutting Concepts

## 8.1 Identity

* `uid` is Samsung Health's id of a stored data point; `null` on payloads the consumer created.
* `clientDataId` (1–36 characters) is the consumer's own key. `SamsungHealthWriter.insert` assigns a random UUID
  when it is missing and returns the samples with it, so a just-inserted sample can be updated or deleted without
  reading it back.
* Update and delete address stored points by `uid`, or by `clientDataId` without one — never by matching values.

## 8.2 Time

* Instants are epoch milliseconds (`…Timestamp`), durations milliseconds (`…Millis`).
* `TimeRange(start, end)` is end-exclusive and interpreted in the device's local time, the way Samsung Health
  groups days; `TimeRange.day()` / `lastDays(n)` build local calendar ranges.
* `zoneOffsetSeconds` is optional on writes; the SDK fills in the device's current offset when it is `null`.
* Date-based SDK operations (energy score reads, local-date aggregations) receive `LocalDateFilter`s covering every
  local date the range touches.

## 8.3 Units

The SDK fixes one unit per field (bpm, %, mmHg, mmol/L, kg, cm, °C, mL, kcal, m, m/s). Payload fields keep that
unit and document it in KDoc; nothing is converted. Only `Aggregation.unit` / `Aggregate.unit` carry unit strings
(`count`, `kcal`, `ms`, `m`, `floor`, `bpm`, `mL`, `s`).

## 8.4 Serialization contract

* Every payload is `@Serializable`; `json` encodes it; the companion `Payload.Factory` offers `decode(json)`,
  `make(from: Map)` (the map is turned into a `JsonElement` and decoded by the same serializer, so map keys equal
  JSON names) and `collect(from: List<Map>)`, which skips invalid maps.
* Sample JSON carries a `type` discriminator (`@SerialName` = `HealthType.identifier`), so `Sample.serializer()`
  decodes mixed lists, e.g. `ChangeSet.upserted`.
* Property names and `@SerialName`s are a public contract; renaming one is a major release.

## 8.5 Errors

| SDK exception | `SamsungHealthException` |
| :--- | :--- |
| `AuthorizationException` (2000 no permission, 2002 not owner, 2003 not allowed by SDK policy, …) | `NotAuthorized` |
| `InvalidRequestException` (1001 invalid input, …) | `InvalidValue` |
| `ResolvablePlatformException` (3000 not installed, 3001 old version, …) | `Resolvable` (pass to `manager.resolve`) |
| any other `HealthDataException` | `Platform(errorCode)` |
| — (library validation) | `InvalidType`, `InvalidValue` |

Every store call **and the request building before it** runs inside `sdkCall { }`, because SDK builders throw
`HealthDataException`s too. The SDK exception is kept as `cause`.

## 8.6 Type registry and exhaustiveness

`HealthType` and `Aggregation` carry no SDK imports; their SDK side is a set of exhaustive `when`s in
`decorator/`. Adding an entry makes the compiler list every place to update. `TypeTest` proves that the
`isReadable` / `isWritable` / `isObservable` flags match the registry and that every value-enum entry maps to the
SDK and back.

## 8.7 Concurrency

All service calls are `suspend` and run on the caller's coroutine context; the library never blocks, never starts
threads and never picks a dispatcher. `observe` is a cold `Flow`; cancelling the collector stops polling. The
facade holds no mutable state; the writer's client-id provider and the observer's clock are injected functions.

## 8.8 Testing

| Level | Tooling | Scope |
| :--- | :--- | :--- |
| Payloads, value types | JUnit 4, kotlin-test | JSON and map round trips over every payload (`Fixtures.allSamples`), invalid input |
| Conversions | real SDK builders (AAR or stub) | every writable payload → `HealthDataPoint` → payload; read-only payloads from built points |
| Services | MockK store, kotlinx-coroutines-test, Robolectric for writes | paging, limits, validation before SDK calls, error wrapping, observer on virtual time |
| Device | Example app | permission flows and real data on a phone |

The suite (97 tests) runs against the real SDK and the stub; Kover enforces ≥ 99% line and ≥ 74% branch coverage (measured 99.94% / 74.5%). Nearly all missed branches are generated by the kotlinx.serialization plugin (`write$Self`, decoding constructors) and are unreachable because payloads always encode defaults.
